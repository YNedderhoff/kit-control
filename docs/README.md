# Documentation

Use these records to understand and change KitControl without a task-specific handoff. Placement, dates, statuses and commit maintenance are defined in [CONTRIBUTING.md](../CONTRIBUTING.md#documentation-lifecycle).

| Area | Authoritative purpose |
| --- | --- |
| [RFCs](rfcs/README.md) | Open proposals, requirements/alternatives still under discussion |
| [ADRs](adrs/README.md) | Accepted decisions, reasons and consequences |
| [Projects](projects/README.md) | Implementation scope, dependencies, acceptance and remaining work |
| [Current documentation](current/README.md) | Existing implementation, usage, evidence and explicit limits |

## Start development

Read [AGENTS.md](../AGENTS.md), [CONTRIBUTING.md](../CONTRIBUTING.md), the relevant decision/project records, and the [development guide](current/development.md). The [editor project](projects/2026-10-25-kitcontrol-editor.md) preserves the complete accepted requirements; its [next bounded task](projects/2026-10-25-kitcontrol-editor.md#next-bounded-task) is maintained there alone.

For device work read the [hardware procedure](current/hardware-test-protocol.md), [API](current/api.md) and [verification limits](current/verification.md). A decision being accepted is not implementation or physical test evidence.
